# 2026-09-21 — F1-16: perfil, porcentajes y tema

- Autor: Claude (Opus 5), a pedido de Braian
- Duración aprox: media sesión

## Objetivo

La pantalla de perfil: editar los porcentajes de carga por defecto y el tema, con la API como
fuente de verdad.

## Qué se hizo

- **Porcentajes**: un campo por porcentaje, con "Agregar" y "Quitar". Las reglas son las de
  `@wasabi-cross/schemas` (enteros de 1 a 100, sin repetidos, hasta 12), las mismas que aplica la
  API; acá sólo se decide **dónde** se muestra cada error.
- **Tema**: se aplica al instante y se guarda en la API. Con sesión, lo guardado manda sobre el
  dispositivo; `localStorage` queda para que no haya parpadeo antes de que cargue la sesión.
- El toggle del header usa el mismo camino: antes cambiaba el tema sólo en el dispositivo y al
  recargar la API lo revertía.

## Decisiones tomadas

- **El error de un porcentaje repetido va en el campo que repite**, no en la lista. El schema
  compartido no puede saberlo (para él es una regla del conjunto), así que la decisión de dónde
  mostrarlo vive en el front, con su propio módulo y sus tests.
- **Cada fila lleva un id propio, no su posición**: al quitar una del medio, React tiene que sacar
  esa fila y no recomponer las de abajo con los valores corridos.
- **Si el guardado del tema falla, el tema vuelve** a lo que dice la API. Es incómodo pero honesto:
  mostrar un tema que no se guardó es peor.
- **No se agregó "Color" al menú**, aunque el mockup 4a lo tiene: el tema ya está en el header y en
  el perfil, y una tercera puerta a lo mismo no agrega nada. Queda anotado por si se quiere.

## Bloqueos / lo que no funcionó

- **Cinco pruebas inversas**, todas detectadas: repetidos que pasan, el error puesto en el campo
  equivocado, guardar sin validar, el tema que no se guarda y la API que no manda al cargar.
- **Un `eslint-disable` de una regla que no existe** (`react/no-array-index-key`) hizo fallar el
  lint. En vez de sacar el comentario se sacó la causa: las filas ahora tienen id propio.
- **Probado a mano contra la API real**: cambiar el tema y verlo guardado; forzar `dark` en el
  dispositivo y comprobar que al recargar gana el `light` de la API; quitar un porcentaje y verlo
  guardado. Apareció un defecto que ningún test veía: los botones "Quitar" se salían del borde
  porque el campo no achicaba. Arreglado.
